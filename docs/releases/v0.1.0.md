# v0.1.0 — Deterministic policy gate and MCP stdio proxy

This is the first tagged release of Agent Runtime Guard for .NET.

The release establishes one concrete pre-execution boundary for AI-agent tool calls without trying to become a general agent framework.

## Included

- deterministic policy evaluation with Allow, RequireApproval, and Deny;
- provider-neutral policy contracts;
- a small HTTP evaluation endpoint;
- a stdio MCP proxy that launches an upstream server as a child process;
- interception of tools/call before upstream execution;
- unchanged forwarding for allowed and non-tool JSON-RPC messages;
- fail-closed handling for malformed client traffic;
- bounded local policy errors that do not echo complete tool arguments;
- integration-style tests proving denied calls do not reach upstream input;
- a reproducible filesystem-server demo policy.

## MCP boundary

The proxy intentionally does not implement MCP negotiation, discovery, notifications, tasks, or extension behavior. Those messages remain owned by the upstream server and are passed through unchanged.

This limits coupling to a particular protocol revision while keeping the tool-execution decision explicit.

## Validation

The release branch is accepted only after the repository restore, build, and test workflow passes on .NET 10.

The test suite covers:

- rule precedence;
- conservative defaults;
- wildcard matching;
- cancellation;
- allowed MCP tool calls;
- blocked MCP tool calls;
- non-tool pass-through;
- upstream error preservation;
- malformed payload fail-closed behavior;
- exclusion of raw tool arguments from local block responses.

## Current boundary

This release does not include:

- approval workflows;
- persistent receipts;
- replay;
- argument-level secret/command inspection;
- agent-specific adapters;
- multi-tenant administration;
- dashboards or hosted services.

The next planned milestone is bounded local decision receipts.
