# v0.2.0 — Bounded local decision receipts

v0.2.0 adds optional local reviewability to the MCP policy path without storing full prompts or tool payloads.

## Highlights

- opt-in SQLite decision receipts;
- deterministic maximum-count retention;
- session-scoped query/export as JSON Lines;
- bounded metadata lengths;
- MCP-to-receipt integration coverage;
- schema-level tests proving sensitive payload fields are absent;
- conservative failure behavior when persistence was explicitly enabled.

## Stored metadata

The receipt schema stores only:

- decision ID;
- evaluation timestamp;
- effect;
- matched rule ID;
- agent ID;
- session ID;
- tool name;
- operation;
- resource.

It does not store:

- prompt text;
- MCP arguments;
- policy reason;
- tags;
- tool result;
- upstream stderr.

## Usage

Enable receipts on the MCP proxy with:

~~~text
--receipts <database-path>
--max-receipts <count>
--session-id <id>
~~~

Query a session with:

~~~text
AgentRuntimeGuard.McpProxy receipts --database <database-path> --session <id> [--limit <1-1000>]
~~~

Output is JSON Lines so it can be redirected to a file or processed by standard command-line tools.

## Failure semantics

Receipt persistence is disabled by default.

When explicitly enabled, a receipt write happens before the decorated evaluator returns the policy decision. A storage failure therefore prevents the integration from continuing with an unrecorded decision.

## Validation

The release is backed by CI coverage for:

- Allow, RequireApproval, and Deny receipts;
- retention;
- session filtering;
- metadata bounds;
- sensitive-column exclusion;
- MCP-to-receipt integration;
- JSONL query/export;
- persistence failure propagation;
- the existing MCP enforcement and policy tests.

## Boundaries

This release does not claim tamper-evident audit, compliance retention, database encryption, multi-tenant administration, or authenticated receipt access.

SQLite is local and unencrypted. Host/file permissions remain the operator's responsibility.
