# v0.3.0 — Local human approval and guarded Cursor setup

v0.3.0 turns the earlier policy-and-receipt foundation into a more usable local enforcement path for MCP clients.

The release adds explicit human approval for `RequireApproval`, bounded in-process telemetry around that wait, and a concrete Cursor setup that keeps the guard between the client and the upstream filesystem server.

## Highlights

- opt-in local human approval for MCP `tools/call`;
- loopback-only bearer-protected approval API;
- explicit approve, reject, and expiry behavior;
- generated or environment-supplied approval tokens;
- bounded approval telemetry through .NET `ActivitySource` and `Meter`;
- runnable in-repository approval demo;
- Cursor MCP presets for Windows and macOS/Linux;
- conservative Cursor workspace policy with Allow / RequireApproval / Deny decisions;
- CI contract tests for the public Cursor preset.

## Approval behavior

When approval is enabled, a `RequireApproval` decision does not reach the upstream MCP server until it is explicitly approved.

The following outcomes remain fail-closed:

- rejection;
- timeout/expiry;
- missing approval provider;
- invalid bearer token;
- broker/provider failure.

Pending approval responses expose bounded decision metadata rather than full MCP arguments or prompts.

## Cursor integration

The release includes a project-level Cursor MCP setup:

~~~text
Cursor
  -> AgentRuntimeGuard.McpProxy
     -> @modelcontextprotocol/server-filesystem
        -> current workspace
~~~

The included workspace policy uses this default posture:

- read/list/search/metadata: Allow;
- write/edit/create/copy-style tools: RequireApproval;
- move/delete/remove-style tools: Deny;
- unclassified tools: RequireApproval.

The preset is intended as a developer integration example, not a production security profile.

## Telemetry

Approval waits emit bounded diagnostics under:

~~~text
AgentRuntimeGuard.Approvals
~~~

The project exposes:

- a completed-approval counter;
- an approval-duration histogram;
- an `approval.wait` activity.

The only project-defined outcome dimension is:

~~~text
approved | rejected | expired | cancelled | error
~~~

No exporter or network sink is enabled by the project.

## Validation

The release is backed by CI coverage for:

- policy precedence and conservative defaults;
- MCP interception and upstream blocking;
- bounded SQLite decision receipts;
- local human approval outcomes;
- approval data minimization;
- telemetry outcome bounds;
- Cursor policy contract;
- Windows and Unix Cursor launch-chain contract.

## Boundaries

This remains an experimental local-first guard.

It does not provide:

- OS process sandboxing;
- network isolation;
- credential brokering;
- remote identity;
- multi-user authorization;
- tamper-evident audit;
- protection when an MCP server is launched outside the guard.

The approval API binds to loopback and uses bearer authentication, but that is not equivalent to OS-user isolation.

See `README.md`, `docs/DEMO.md`, `docs/CURSOR.md`, and `SECURITY.md` for the current trust boundary.
